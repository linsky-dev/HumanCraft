# 模型效果评测方案

本文规定 HumanCraft 公开开发任务的配对比较流程，描述正式实验设计和已有工具。实际开发试跑见 [评测结果](BENCHMARK-RESULTS.md)。

## 实验分组

新实验对同一精确模型、执行器、配置、任务和重复编号设置四组匹配条件。

| 组别 | 条件 | 默认行为 |
|---|---|---|
| A `baseline` | 不加载设计技能 | 默认包含 |
| B `generic` | 通用 UX 清单 | 默认包含 |
| C `previous` | 冻结版技能对照 | 默认 v0.5，显式指定 `--frozen-v06-control` 时使用 v0.6 |
| D `candidate` | 准备实验时的当前 HumanCraft 源码 | 默认包含，并纳入计划哈希 |

历史默认设置中 C 组仍使用 v0.5。要运行冻结版 v0.6 对照，使用以下命令。

```sh
python bench/experiment.py prepare experiment configs.json --trials 3 --seed 20261124 --frozen-v06-control
```

两个模型配置、八个公开开发任务、每组每任务重复三次时，会生成 192 个独立任务包。准备阶段不会调用模型。每个任务包都记录输入哈希，v0.6 计划还会记录冻结包哈希。候选源码在准备时纳入计划，因此之后若有源码变化，该计划校验会失败。

## 预先冻结的实验条件

开始运行前，冻结计划并保留 `plan.sha256`。记录模型和执行器的精确版本、生成参数、工具权限、配置和记忆设置、任务初始数据、时间与 token 预算、任务顺序随机种子、验证器版本及候选源码哈希。每个任务包使用独立工作区和会话。被测 Agent 不应接触验证器、参考实现、分组映射和此前输出。

初步比较使用每任务、每组各三次独立重复。各组使用相同任务提示、初始应用、工具、运行约束和预算。通用清单没有按长度匹配，因此 token 开销可能受到提示长度差异影响。技能调用信息由操作员记录，不能证明客户端实际激活技能或模型身份。

## 判分和统计

`bench/verify.py` 根据任务契约独立检查返回的应用，并报告 PASS、FAIL、ERROR 或 Agent 执行失败。缺失运行、执行错误和未知关键检查均保留在结果中。汇总只比较完整匹配的 A/B/C/D 组，先按任务重复求平均，再对任务等权汇总，严重及关键失败单独报告，并根据任务层结果进行 bootstrap。单个任务中的重复不会视为独立任务。有效任务不足两个时不报告 bootstrap 区间。

固定公开任务集用于开发和回归，不是隐藏测试集，其参考实现由项目维护者编写。在这些案例上的结果只描述所记录设置下这些案例的表现，无法证明泛化能力、普遍生产力提升、真实用户满意度或跨模型的因果收益。完整运行只表明该矩阵已覆盖，不构成发布认证。

报告至少包含计划哈希、压缩包和候选源码哈希、模型、执行器及配置、全部已尝试和缺失运行、各组按任务平均的 PASS 率、D 相对 A/B/C 的百分点差、任务聚类不确定性区间、严重及关键失败、附覆盖数量的 token 和时长中位数、技能调用观察和负增益任务。ERROR 与 FAIL 分开统计，并保留原始日志和判分结果。不同模型标识或执行器配置分层报告。

## 截至 2026-11-25 的证据状态

仓库包含确定性的四臂实验工具和合成浏览器校准数据。独立模型比较仍为 `NOT_RUN`。恢复并合并 v0.6 完整源码不代表已完成模型实验。真人可用性测试和独立留出集评测也仍为 `NOT_RUN`。
