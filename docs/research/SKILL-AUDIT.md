# 技能审查

| 发现 | 根因及影响 | 修复和验收 |
| --- | --- | --- |
| 关键门禁仅凭静态检查可报通过 | 评分函数对通过和失败使用相同的证据类型集合。完整静态检查可误报没有关键阻碍 | 静态检查可以报告失败。静态检查给出的通过声明带 `executed-test-required` 阻断。CLI 测试同时检查已观察失败没有被掩盖 |
| 重复 JSON 键和非有限数被默认解码器接受 | 解码器覆盖重复键，证据的冲突字段会消失 | 两个 CLI 共享严格解析器。旧版负向样本错误地返回成功，新版明确拒绝。普通合法轨迹继续通过 |
| 主体一致性容易被误读为轨迹检查范围 | 事件只记录操作 ID 及目标范围 | 参考模块说明主体与角色变化仍需独立后端证据。事件协议兼容原记录 |

原始验收由独立 Reviewer 复现。复现测试和 CLI 保留在 [测试源码](../../tests/test_skill_evidence.py)。验证卡点、正式模型增益及视觉效果见 [发布证据](RELEASE-READINESS.md)。
